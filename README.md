# RPumpkin

**RPumpkin** is a unified solution to add Minecraft RolePlay features to a [Pumpkin](https://github.com/Pumpkin-MC/Pumpkin) server.

It is a Pumpkin plugin (WebAssembly, written in Rust) that bundles the essential RolePlay building blocks: persistent character sheets, formatted RP chat, and RolePlay action commands.

## Features

### Character sheets
- `/sheet` — display your sheet
- `/sheet <player>` — display another player's sheet
- `/sheet set name <name>` — set your character's RP name
- `/sheet set job <job>` — set your character's job
- `/sheet set description <text>` — set your character's backstory/description

Sheets are persisted in `plugins/data/rpumpkin/sheets.json` and reloaded on startup.

### RolePlay commands
- `/roll [faces]` — roll a die (2 to 1000 faces, 100 by default), result announced to everyone
- `/me <action>` — describe an action in third person ("* Jean hits *")
- `/do <event>` — describe an RP event/state
- `/hrp <message>` — Out-of-Character message, clearly marked
- `/rp [true|false]` — enable/disable RP mode (toggles if no argument)

### Job outfits
- `/job <fermier|mineur>` — apply the job outfit while keeping the player's head

Since the Minecraft skin is a single 64x64 texture, the outfit is a composite: the player's head + the outfit body. Outfits are generated by `skins/gen_skins.py` (64x64 PNG, transparent head area) and must be placed in the plugin data folder (`plugins/data/rpumpkin/tenues/`).

**API constraint**: the 0.2 plugin API does not expose an HTTP client, so automatic upload to mineskin.org is not possible from the plugin. Composites must be pre-generated. Automatic application (downloading the player's skin + mineskin upload) will be enabled once the API exposes an HTTP client.

### RP chat
When RP mode is enabled, the player's chat messages are automatically formatted as `[RP] <RPName>: message`, using the sheet name instead of the Minecraft username.

### Configurable books
- `/book` — list available books
- `/book <id>` — receive the book in your inventory (first free slot)

Content is defined server-side, with no recompilation needed: each JSON file placed in `plugins/data/rpumpkin/livres/` becomes a usable in-game book. Example `plugins/data/rpumpkin/livres/reglement.json`:

```json
{
  "titre": "City Rules",
  "auteur": "The Town Hall",
  "pages": [
    "&lCity Rules&\n&7Welcome, citizen!",
    "&eArticle 1&f: remain courteous toward other residents.",
    "&eArticle 2&f: OOC chat is done via /hrp."
  ]
}
```

Fields:
- `titre` (default: `Sans titre`) — book title and item name
- `auteur` (default: `Serveur`) — author shown in the book
- `pages` — list of strings (or a single string for a single page); legacy color codes supported (`&e`, `&l`, `&o`...), `\n` for a line break. A Minecraft book is limited to 100 pages / 255 characters per page in game.

Books are loaded when the plugin starts. The book `id` is the file name without extension.

### Nametag line of sight (`sightline`)

Nametags are only visible when the line of sight between the two players' eyes is clear — per viewer (each player has their own scoreboard with a hidden team, `nametag-visibility = never`), the same idea as VisTag on Paper. Transparent blocks (glass, leaves, water...) do not hide nametags; only full opaque cubes do, unless configured otherwise.

- Every `check-interval-ticks`, each pair of players in the same world is re-evaluated (admin toggle, sneak hiding, max distance, optional FOV cone, line of sight) and added to / removed from the viewer's hidden team.
- **Exact raycast** on block collision shapes (voxel shapes, segment-vs-box intersection), with a faster coarse mode (`exact-raycast: false`).
- Admin commands (permission `rpumpkin:command.sightline`, operators by default):
  - `/sightline toggle <players...>` — enable/disable nametag filtering for players (persisted)
  - `/sightline exclude add|remove|list <block>` — blocks that never hide nametags (highest priority)
  - `/sightline include add|remove|list <block>` — blocks that always hide nametags, even transparent ones
  - `/sightline reload` — reload the configuration

Settings are persisted in `plugins/data/rpumpkin/sightline.json` (created with defaults on first startup):

```json
{
  "check-interval-ticks": 10,
  "max-distance": 64,
  "hide-when-sneaking": true,
  "fov-cone-degrees": 0,
  "exact-raycast": true,
  "excluded": [],
  "included": [],
  "toggled-off-players": []
}
```

Priority: `excluded` > `included` > default behavior (full opaque cube). Block IDs accept both `glass` and `minecraft:glass`.

Note: per-viewer hiding relies on the Java-protocol scoreboard, so Bedrock players are not affected.

### Command aliases (`alias`)

Linux-style command aliases, stored in a server-side config file: `plugins/data/rpumpkin/aliases.json` (created empty on first startup):

```json
{
  "aliases": {
    "salut": "me salutes everyone",
    "home": "tp @s 0 64 0"
  }
}
```

Each key becomes an in-game command `/<key>`. Any arguments typed after the alias are appended to the target command: `/home extra` runs `tp @s 0 64 0 extra`. The target runs through the server command dispatcher **as the original sender**, so the target command's own permissions still apply (no privilege escalation). Recursive aliases are capped at 16 levels.

Alias commands are registered when the plugin loads, so a **new name** added to the file becomes usable after a server restart; the target of an **existing** alias is looked up on every execution, so editing it (or `/alias reload`) takes effect immediately. Names are lowercased and cannot contain spaces, a leading `/`, or collide with the plugin's own commands (`sheet`, `roll`, `me`, `do`, `hrp`, `rp`, `job`, `book`, `sightline`, `alias`).

Admin commands (permission `rpumpkin:command.alias.admin`, operators by default):
- `/alias` or `/alias list` — list aliases and their targets
- `/alias add <name> <command...>` — create/replace an alias (persisted to `aliases.json`)
- `/alias remove <name>` — delete an alias (persisted)
- `/alias reload` — reload `aliases.json` from disk

## Feature configuration

Each plugin feature (not the plugin itself) can be enabled or disabled via `plugins/data/rpumpkin/config.json`, automatically created with default values on first startup:

```json
{
  "fonctionnalites": {
    "fiches": true,
    "chat_rp": true,
    "commandes_rp": true,
    "metier": true,
    "livres": true,
    "sightline": true,
    "alias": true
  }
}
```

| Key | Controlled feature |
|-----|--------------------|
| `fiches` | Character sheets (`/sheet`, `sheets.json` persistence) |
| `chat_rp` | RP chat formatting (event handler) |
| `commandes_rp` | `/roll`, `/me`, `/do`, `/hrp`, `/rp` commands |
| `metier` | `/job` command and outfits |
| `livres` | `/book` command and server books |
| `sightline` | Nametags visible only with line of sight (`/sightline`) |
| `alias` | Configurable command aliases (`aliases.json`, `/alias`) |

A disabled feature registers neither its commands, nor its permissions, nor its handlers — it is completely absent from the server until re-enabled (persisted data such as `sheets.json` is kept). The configuration is read when the plugin starts.

## Permissions

| Node | Description | Default |
|------|-------------|---------|
| `rpumpkin:command.sheet` | Manage your character sheet | Allowed |
| `rpumpkin:command.rp` | RolePlay commands (roll, me, do, hrp) | Allowed |
| `rpumpkin:command.job` | Choose your job outfit | Allowed |
| `rpumpkin:command.book` | Receive a server book | Allowed |
| `rpumpkin:command.sightline` | Manage nametag visibility (`/sightline`) | Operators |
| `rpumpkin:command.alias` | Use command aliases | Allowed |
| `rpumpkin:command.alias.admin` | Manage command aliases (`/alias`) | Operators |

The plugin also requests permissions to access its data folder (`fs.read.data`, `fs.write.data`).

## Platform compatibility

The plugin is compiled to WebAssembly (`wasm32-wasip2`): a single `rpumpkin.wasm` runs on every architecture supported by the Pumpkin server — x86_64, ARM64 (Raspberry Pi 5, Apple Silicon). No Pi 5-specific build is needed; only the Pumpkin server binary must be the `aarch64` version.

### Pumpkin server compatibility

The plugin is built against the Pumpkin `0.2.2+26.3-26.60` plugin API and stays loadable on both supported server releases: `0.2.1+26.3-26.51` and `0.2.2+26.3-26.60`.

It uses the v0.1 WIT ABI (`pumpkin:plugin@0.1.0`), which is byte-identical between those two Pumpkin releases, so the compiled component exports `pumpkin:plugin/metadata@0.1.0` and both servers route it to their isolated v0.1 plugin host — no `ApiMismatch`. The CI builds the WASM against both tags on every push/PR (`.github/workflows/ci.yml`, `compat` job), and the extracted component interface of the two builds is identical. Warning: a plugin built against the 0.2.0 API no longer loads on 0.2.1+ servers, because the 0.2.1 server changed some v0.1 event records. Once `pumpkin-plugin-api 0.2.2` is published on crates.io, the git dependency in `Cargo.toml` can be switched back to a version requirement.

## CI / GitHub Release

- `.github/workflows/ci.yml` — on every push/PR: `cargo fmt --check`, `cargo clippy -D warnings`, WASM build, plus a `compat` matrix job that builds the WASM against each supported Pumpkin tag (`0.2.2+26.3-26.60`, `0.2.1+26.3-26.51`).
- `.github/workflows/release.yml` — the single release pipeline, triggered on every push to `main` and on every `vX.Y.Z` tag push. On a push to `main` it reads `version` from `Cargo.toml` and releases only if the GitHub release `v<version>` does not exist yet (idempotent: merges without a version bump do nothing); on a tag push it always releases. Steps: WASM build, tag + GitHub release with `rpumpkin.wasm` attached, publish to the Pumpkin Market.

To publish a new version, no tag to push: bump `version` in `Cargo.toml` in a PR, merge it to `main` — the release is created automatically.

### Publishing to the Pumpkin Market

Market publishing is done by the `publish-to-pumpkin-market` action (from [filiphsps/pumpkin-plugins](https://github.com/filiphsps/pumpkin-plugins)). Prerequisites:

1. Create a "rpumpkin" plugin entry on [market.pumpkinmc.org](https://market.pumpkinmc.org) (first time only).
2. Generate a Market API token with the `plugins:update` and `plugins:versions:upload` scopes.
3. Add it as the `PUMPKIN_MARKET_TOKEN` secret in `Settings > Secrets and variables > Actions`.

For each new version released on `main`, the version is then published automatically to the Market (`alpha` track), in addition to the GitHub release.

## Build

Prerequisites: Rust (via rustup) and the WASI target:

```bash
rustup target add wasm32-wasip2
cargo build --release
```

Place the `target/wasm32-wasip2/release/rpumpkin.wasm` file in the `plugins/` folder of the Pumpkin server.

## Project structure

```
├── .cargo/config.toml   # wasm32-wasip2 build target
├── Cargo.toml
├── skins/               # outfit generator + test outfits (b64)
└── src/
    ├── lib.rs           # full plugin
    ├── aliases.rs       # command aliases module (aliases.json, /alias)
    ├── books.rs         # configurable books module (written_book_content encoding)
    ├── config.rs        # feature configuration module
    ├── sightline.rs     # nametag line-of-sight module (per-player scoreboard teams)
    └── skins/           # job outfits module (head/body composite)
```
