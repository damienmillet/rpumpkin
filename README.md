# RPumpkin

**RPumpkin** is a unified solution to add Minecraft RolePlay features to a [Pumpkin](https://github.com/Pumpkin-MC/Pumpkin) server.

It is a Pumpkin plugin (WebAssembly, written in Rust) that bundles the essential RolePlay building blocks: persistent character sheets, formatted RP chat, and RolePlay action commands.

## Features

### Character sheets
- `/fiche` — display your sheet
- `/fiche <player>` — display another player's sheet
- `/fiche set nom <name>` — set your character's RP name
- `/fiche set metier <job>` — set your character's job
- `/fiche set description <text>` — set your character's backstory/description

Sheets are persisted in `plugins/data/rpumpkin/sheets.json` and reloaded on startup.

### RolePlay commands
- `/roll [faces]` — roll a die (2 to 1000 faces, 100 by default), result announced to everyone
- `/me <action>` — describe an action in third person ("* Jean hits *")
- `/do <event>` — describe an RP event/state
- `/hrp <message>` — Out-of-Character message, clearly marked
- `/rp [true|false]` — enable/disable RP mode (toggles if no argument)

### Job outfits
- `/metier <fermier|mineur>` — apply the job outfit while keeping the player's head

Since the Minecraft skin is a single 64x64 texture, the outfit is a composite: the player's head + the outfit body. Outfits are generated by `skins/gen_skins.py` (64x64 PNG, transparent head area) and must be placed in the plugin data folder (`plugins/data/rpumpkin/tenues/`).

**API constraint**: the 0.2 plugin API does not expose an HTTP client, so automatic upload to mineskin.org is not possible from the plugin. Composites must be pre-generated. Automatic application (downloading the player's skin + mineskin upload) will be enabled once the API exposes an HTTP client.

### RP chat
When RP mode is enabled, the player's chat messages are automatically formatted as `[RP] <RPName>: message`, using the sheet name instead of the Minecraft username.

### Configurable books
- `/livre` — list available books
- `/livre <id>` — receive the book in your inventory (first free slot)

Content is defined server-side, with no recompilation needed: each JSON file placed in `plugins/data/rpumpkin/livres/` becomes a usable in-game book. Example `plugins/data/rpumpkin/livres/reglement.json`:

```json
{
  "titre": "City Rules",
  "auteur": "The Town Hall",
  "pages": [
    "&lCity Rules&\n&7Welcome, citizen!",
    "&eArticle 1&f: remain courteous toward other residents.",
    "&eArticle 2&f: OOC chat is done via /hrp."
  ]
}
```

Fields:
- `titre` (default: `Sans titre`) — book title and item name
- `auteur` (default: `Serveur`) — author shown in the book
- `pages` — list of strings (or a single string for a single page); legacy color codes supported (`&e`, `&l`, `&o`...), `\n` for a line break. A Minecraft book is limited to 100 pages / 255 characters per page in game.

Books are loaded when the plugin starts. The book `id` is the file name without extension.

## Feature configuration

Each plugin feature (not the plugin itself) can be enabled or disabled via `plugins/data/rpumpkin/config.json`, automatically created with default values on first startup:

```json
{
  "fonctionnalites": {
    "fiches": true,
    "chat_rp": true,
    "commandes_rp": true,
    "metier": true,
    "livres": true
  }
}
```

| Key | Controlled feature |
|-----|--------------------|
| `fiches` | Character sheets (`/fiche`, `sheets.json` persistence) |
| `chat_rp` | RP chat formatting (event handler) |
| `commandes_rp` | `/roll`, `/me`, `/do`, `/hrp`, `/rp` commands |
| `metier` | `/metier` command and outfits |
| `livres` | `/livre` command and server books |

A disabled feature registers neither its commands, nor its permissions, nor its handlers — it is completely absent from the server until re-enabled (persisted data such as `sheets.json` is kept). The configuration is read when the plugin starts.

## Permissions

| Node | Description | Default |
|------|-------------|---------|
| `rpumpkin.command.fiche` | Manage your character sheet | Allowed |
| `rpumpkin.command.rp` | RolePlay commands (roll, me, do, hrp) | Allowed |
| `rpumpkin.command.metier` | Choose your job outfit | Allowed |
| `rpumpkin.command.livre` | Receive a server book | Allowed |

The plugin also requests permissions to access its data folder (`fs.read.data`, `fs.write.data`).

## Platform compatibility

The plugin is compiled to WebAssembly (`wasm32-wasip2`): a single `rpumpkin.wasm` runs on every architecture supported by the Pumpkin server — x86_64, ARM64 (Raspberry Pi 5, Apple Silicon). No Pi 5-specific build is needed; only the Pumpkin server binary must be the `aarch64` version.

### Pumpkin server compatibility

The plugin is built against the Pumpkin `0.2.1+26.3-26.51` plugin API (v0.1 WIT ABI). Because the 0.2.1 server changed some v0.1 event records, a plugin built against the old 0.2.0 API no longer loads on a 0.2.1 server (`ApiMismatch`); this build fixes that. Once `pumpkin-plugin-api 0.2.1` is published on crates.io, the git dependency in `Cargo.toml` can be switched back to a version requirement.

## CI / GitHub Release

- `.github/workflows/ci.yml` — on every push/PR: `cargo fmt --check`, `cargo clippy -D warnings`, WASM build.
- `.github/workflows/release.yml` — on a `vX.Y.Z` tag: build, create a GitHub release with `rpumpkin.wasm` attached, then publish to the Pumpkin Market.

To publish a new version:

```bash
git tag v0.1.1
git push origin v0.1.1
```

### Publishing to the Pumpkin Market

Market publishing is done by the `publish-to-pumpkin-market` action (from [filiphsps/pumpkin-plugins](https://github.com/filiphsps/pumpkin-plugins)). Prerequisites:

1. Create a "rpumpkin" plugin entry on [market.pumpkinmc.org](https://market.pumpkinmc.org) (first time only).
2. Generate a Market API token with the `plugins:update` and `plugins:versions:upload` scopes.
3. Add it as the `PUMPKIN_MARKET_TOKEN` secret in `Settings > Secrets and variables > Actions`.

For each pushed tag, the version is then published automatically to the Market (`stable` track), in addition to the GitHub release.

## Build

Prerequisites: Rust (via rustup) and the WASI target:

```bash
rustup target add wasm32-wasip2
cargo build --release
```

Place the `target/wasm32-wasip2/release/rpumpkin.wasm` file in the `plugins/` folder of the Pumpkin server.

## Project structure

```
├── .cargo/config.toml   # wasm32-wasip2 build target
├── Cargo.toml
├── skins/               # outfit generator + test outfits (b64)
└── src/
    ├── lib.rs           # full plugin
    ├── books.rs         # configurable books module (written_book_content encoding)
    ├── config.rs        # feature configuration module
    └── skins/           # job outfits module (head/body composite)
```
